🤖 W.E.B.S is a Jarvis-inspired personal AI operating system built
in Python. It features a full-screen animated HUD face, voice I/O,
desktop automation, web browsing, file management, and multi-provider
LLM support — all orchestrated by a modular, event-driven brain.

🧠 THE BRAIN — Central Orchestrator
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The Brain class (~900 lines) is the core controller that:

  1️⃣  🔌 Initializes all subsystems (EventBus, StateManager, Memory,
     Cache, ModelManager, PromptManager, Tools, Planner, Learner,
     Dispatcher, Evolver)

  2️⃣  📥 Processes user input via brain.process(user_input):
     • Stores message in memory
     • Detects actions via regex pattern matching
     • Executes actions (open apps, files, research, web, mouse/keyboard)
     • Builds system prompt with live context + tools + learner + memory
     • Sends messages to the active LLM provider
     • Stores response and auto-speaks if voice is active
     • Publishes events for UI updates

  3️⃣  🔗 Supports compound commands:
     "research snakes and put it in a file called report.txt and open it"

🎯 ACTION DETECTION — Regex-Based NLU
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

48 action types with 50+ regex patterns:

  📂 FILE OPS     create, read, delete, copy, move, rename,
                  compress, extract

  🖥️ APP OPS      open/close (firefox, chrome, spotify, discord, etc.)

  🖱️ DESKTOP      mouse move/click/scroll, keyboard type/press/hotkey

  🌐 WEB          browse, search, open news, web task

  🧠 MEMORY       remember, remind

  🔍 RESEARCH     full research reports with live search

  🖼️ IMAGES       generate images via Pollinations AI

  ⌨️ COMMANDS      run terminal commands

  📝 NOTES/TASKS  create notes, add/complete tasks

  🔗 COMPOUND     splits on "and" / "then" for chained commands

🎨 JARVIS HUD FACE — Full-Screen Animated Interface
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

680 lines of pygame magic:

  💫 Pulsing orange core with gradient and glow
  🔄 Rotating arc segments (3 rings, different speeds/colors)
  ⬡ Rotating hexagonal frames (double-hex, counter-rotating)
  ✨ 140 floating particles with wobble physics
  📊 40 audio visualizer bars at the bottom
  🔍 Scan line with trailing glow
  🌑 Vignette overlay for cinematic depth
  📐 HUD corner brackets and brand text
  💬 Chat input box at the bottom
  📄 Response display (top-left, fades out)
  📍 Mode indicator (IDLE / THINKING / LISTENING / SPEAKING)
  📝 Status text and key hints

  All visuals react to audio_energy:
    💤 IDLE       → calm, minimal energy
    🤔 THINKING   → medium pulse, faster particles
    🎤 LISTENING  → rhythmic energy
    🔊 SPEAKING   → high energy bars, maximum pulse

🗣️ VOICE SYSTEM — Full Voice I/O
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  🎤 SPEECH-TO-TEXT (stt.py)
     Dual backend with automatic fallback:
     1. faster-whisper (primary) — Local Whisper, CPU int8
     2. SpeechRecognition + Google (fallback) — Online STT
     • Automatic ALSA capture unmute
     • PulseAudio device discovery
     • Ambient noise calibration
     • Wake word detection (optional)
     • Continuous listening or single listen_once()

  🔊 TEXT-TO-SPEECH (tts.py)
     Piper TTS — fast, offline, British voice:
     • Model: en_GB-alan-medium (Piper ONNX)
     • Voice presets: default, alfred, jarvis, british
     • Faster speech (length_scale=0.82), natural noise

  🎛️ VOICE ENGINE (engine.py)
     High-level orchestrator:
     • Async speak queue (background thread)
     • speak() (blocking) and speak_async() (queued)
     • Voice profile management

  🔔 SPEAKER (speaker.py)
     Event-driven auto-speaker:
     • Subscribes to BRAIN_RESPONDING events
     • Automatically speaks every response
     • Publishes VOICE_SPEAKING / VOICE_IDLE for face reactivity

🧠 INTELLIGENCE MODULES
━━━━━━━━━━━━━━━━━━━━━━━━

  📋 PLANNER (brain/planner.py)
     Analyzes user intent without executing anything:
     • Classifies: conversation / information / automation / memory
     • Detects required tools: browser, filesystem, media, system, web
     • Flags dangerous actions for confirmation
     • Produces a structured Plan dataclass

  🏷️ MESSAGE ROUTER (brain/routing.py)
     Classifies messages into types:
     • Casual: greetings, thanks, ok, lol
     • Work: build, fix, deploy, search, code
     • Command: open, close, list, set, send
     • Question: anything with ?
     • should_use_fast_model() — routes casual to cheaper models

  📈 USAGE LEARNER (brain/learner.py)
     Tracks usage patterns:
     • Logs every task (type, description, project, success)
     • Fuzzy-matches project names with recency + frequency boosting
     • Provides context for LLM: "Frequent tasks: search(12), build(5)"
     • Session stats: task count, success rate, elapsed time

  🧬 TEMPLATE EVOLVER (brain/evolution.py)
     Self-improvement from failures:
     • Logs failures with pattern detection
     • After 3+ failures, generates prevention rules
     • Injects lessons into LLM: "LESSONS LEARNED: Prevent missing_import..."

  📡 DISPATCHER (brain/dispatcher.py)
     Tracks in-flight automation tasks:
     • Task lifecycle: PENDING → RUNNING → COMPLETED/FAILED
     • JSON persistence
     • Formats active/recent tasks for LLM context

  💡 SUGGESTIONS (brain/suggestions.py)
     Post-task heuristics (no LLM calls):
     • Missing tests → "Want me to add some?"
     • Missing README → "Shall I create one?"
     • Missing requirements.txt → "Want me to generate one?"

💾 MEMORY SYSTEM
━━━━━━━━━━━━━━━━

  📝 IN-MEMORY (brain/memory.py)
     Simple JSON-backed storage:
     • Conversation history (role/content)
     • User preferences (key/value)
     • Auto-saves to memory/history.json and preferences.json

  🗄️ SQLITE MEMORY (brain/memory_sqlite.py)
     Persistent memory with FTS5 full-text search:
     • memories table — facts with importance, FTS5 indexed
     • tasks table — todo items with priority, status, due dates
     • notes table — topic/content notes
     • Auto-synced FTS triggers for real-time search
     • build_context() injects key facts + tasks into LLM prompts

     Opens news sites, searches topics, fetches headlines

  🌐 NETWORK (network.py)

🔧 INFRASTRUCTURE
━━━━━━━━━━━━━━━━━━

  📡 EVENT BUS (brain/event_bus.py)
     Thread-safe pub/sub system:
     • 25+ event types (system, brain, planner, voice, memory)
     • Background processing thread (10ms poll)
     • Wildcard + typed subscribers

  🔄 STATE MANAGER (brain/state.py)
     Finite state machine:
     • States: IDLE, INITIALIZING, LISTENING, THINKING, SEARCHING,
       FETCHING, EXECUTING, SPEAKING, WAITING, ERROR, SLEEPING
     • State history with duration tracking

  💾 CACHE (brain/cache.py)
     LRU cache with TTL:
     • Max 500 entries, 1-hour TTL
     • Thread-safe, hit/miss/eviction stats

  👤 SESSION MANAGER (brain/session.py)
     User session tracking:
     • UUID-based sessions with active/paused/ended
     • Max 100 sessions with auto cleanup

  🔧 TOOL REGISTRY (brain/tools.py)
     Decorator-based tool registration:
     • Auto-extracts parameter info from function signatures
     • Supports async tools
     • 7 categories: SEARCH, WEB, AUTOMATION, FILE, SYSTEM, UTILITY, AI
